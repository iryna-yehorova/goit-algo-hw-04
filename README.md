# goit-algo-hw-04

## Task 1

```bash
python3 task_1.py path/to/source [path/to/destination]
```

If the destination path is omitted, files are copied to `dist` in the current
folder. Subfolders are named after file extensions (for example, `txt`). Files
without an extension go to `no_extension`. If files from different folders have
the same name and extension, a number is added to the later copy's name.

## Task 2

```bash
python3 task_2.py
```

Enter a recursion level of 0 or higher. The Koch snowflake opens in a Turtle
graphics window. Level 0 draws a triangle; higher levels add more detail.

## Завдання 3: порівняння алгоритмів сортування

Запуск вимірювань:

```bash
python3 task_3.py
```

Програма порівнює сортування вставками, злиттям і вбудовану функцію `sorted`
(Timsort). Для кожного розміру створюються чотири набори: випадковий,
відсортований, зворотно відсортований і майже відсортований (1% випадкових
обмінів). Перед вимірюванням перевіряється правильність результату. Кожен час
вимірюється `timeit.repeat` тричі; у таблиці наведено найменший час одного
сортування в мілісекундах. Вимірювання виконано на macOS arm64, Python 3.13.14.

Теоретично сортування вставками має складність `O(n)` на вже відсортованому
масиві та `O(n²)` у середньому й найгіршому випадках. Сортування злиттям має
`O(n log n)` у всіх випадках. Timsort використовує впорядковані ділянки
масиву, сортування вставками для коротких ділянок і злиття ділянок;
його найкращий випадок — `O(n)`, найгірший — `O(n log n)`.

| Дані | Кількість | Вставками, мс | Злиттям, мс | Timsort, мс |
|---|---:|---:|---:|---:|
| Випадкові | 1 000 | 15.069 | 1.025 | 0.050 |
| Відсортовані | 1 000 | 0.071 | 0.681 | 0.003 |
| Зворотний порядок | 1 000 | 28.569 | 0.724 | 0.006 |
| Майже відсортовані | 1 000 | 0.571 | 0.815 | 0.013 |
| Випадкові | 3 000 | 140.293 | 3.869 | 0.198 |
| Відсортовані | 3 000 | 0.212 | 2.405 | 0.011 |
| Зворотний порядок | 3 000 | 274.465 | 2.436 | 0.021 |
| Майже відсортовані | 3 000 | 3.116 | 2.905 | 0.035 |
| Випадкові | 10 000 | 1614.391 | 13.548 | 0.801 |
| Відсортовані | 10 000 | 0.714 | 8.640 | 0.041 |
| Зворотний порядок | 10 000 | 3233.612 | 9.190 | 0.083 |
| Майже відсортовані | 10 000 | 45.288 | 11.506 | 0.129 |

### Висновки

- На випадкових даних при збільшенні масиву з 1 000 до 10 000 елементів час
  сортування вставками зріс приблизно у 107 разів. Це узгоджується з
  квадратичною складністю `O(n²)`. На вже відсортованих даних він зріс
  приблизно у 10 разів, що відповідає найкращому випадку `O(n)`.
- Час сортування злиттям на випадкових даних зріс приблизно у 13 разів.
  Це узгоджується з оцінкою `O(n log n)`. На відсортованих даних реалізація
  все одно розбиває масив і зливає частини.
- Timsort показав найменший час у кожному тесті. На 10 000 випадкових чисел
  він був приблизно у 17 разів швидшим за цю реалізацію сортування злиттям
  і приблизно у 2 000 разів швидшим за сортування вставками. Його
  адаптивність особливо помітна на впорядкованих даних.
- Timsort використовує ідеї сортування злиттям та вставками, але самі ці
  вимірювання підтверджують ефективність готової реалізації, а не ізольований
  вплив поєднання алгоритмів: `sorted` також реалізована в оптимізованому
  коді C, тоді як два інші алгоритми тут написані на Python. У звичайних
  задачах доцільно
  використовувати `sorted()` або метод `list.sort()`.
